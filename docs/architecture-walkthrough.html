The constraint that decided the shape

Verified empirically, not assumed

The obvious way to split a Compose file is one file per service, reassembled with include. The obstacle is how this stack currently shares configuration: a YAML anchor merged into every service.

Anchors do not survive the split. They are scoped to a single YAML document, and include is applied after parsing — so an alias can never reach an anchor in another file. Upstream closed this as won't-fix and points to extends.

That single mechanic cascades. Because extends inherits depends_on keys but doesn't import the services they name, the shared fragment can only ever carry restart, logging and networks. And because network, volume and environment identity can't live inside a module while service definitions can, the architecture is a microkernel whether or not anyone chose one.

Twenty-one invariants

Grouped by what each one protects

A decision earns a place here only if two independently-built modules could choose incompatibly, the call is non-obvious, and it's a real trade-off. Everything else is deferred.

Data that cannot be recovered 2 decisions

AD-5Volume names are frozen

A renamed volume is a new volume — the old one orphans and the service starts empty, silently. A module’s volumes: stanza carries the identifier and nothing else, and a module never declares the shared network at all — Compose v2 rejects an included file that names a keyed root resource. object-storage keeps minio-data.

AD-12Stop → write → restart

Any write to another module's state stops its dependents first. Covers realm import and Postgres restore, which rewrites the Keycloak database.

Composition mechanics 6 decisions

AD-1extends, never anchors

Anchors can't cross file boundaries. The base fragment is referenced by extends and never included.

AD-2Base declares no references

No depends_on, links, volumes_from. One-shot helpers must override restart: "no".

AD-6Closure-validity

A module validates with its dependency closure. The naive standalone form passed while checking nothing.

AD-7Bundle names are Core-owned

Membership sits in each module; the name list sits in Core, or CI has nothing to iterate.

AD-8One primary service + helpers

Helpers share their primary's profile set exactly. The contract check runs both directions.

AD-15Dependencies point inward

A module never edits another module's file.

Correctness gates 5 decisions

AD-3depends_on is the gate

config -q already refuses an invalid selection. No bespoke resolver — but it's blind to port collisions.

AD-16Selection resolves to closure

Selecting keycloak alone legitimately fails. The resolver expands it before Compose sees it.

AD-17Ports from one table

Two modules on one host port both validate, then up half-starts. CI parses rendered config for duplicates.

AD-18Selection is never empty

Everything profiled means a bare up would start nothing at exit 0. The resolver refuses.

AD-19CI fails loudly or not at all

No check skips for a missing tool. Iterates every module and every bundle.

Shared namespaces 3 decisions

AD-4Two-tier configuration

Module variables are prefixed; contract variables like AWS_ENDPOINT_URL are SDK-dictated and get one registered owner.

AD-14Declare what you need

Keycloak's database requirement lives in Keycloak's file, not buried in POSTGRES_EXTRA_DATABASES.

AD-11Tags in .env, annotated

Renovate skips repo:${VAR:-tag}, so updates run through a regex manager over .env.

Process and admission 5 decisions

AD-9pixi is the task surface

Today make lint exits 0 having skipped shellcheck. No task may branch on command -v.

AD-10Smoke checks are module-owned

Driven by the resolved selection. The runner fails if that selection is empty.

AD-21Scripts are verified like code

select.sh is load-bearing for four invariants. A bug in it looks exactly like success.

AD-20Catalog admission policy

OSI license, no auth token, no privileged host access, maintained upstream. Security posture stays fixed, not improved.

AD-13Observability stays five containers

otel-lgtm would discard two gotchas already solved here. Weight is answered by not starting the bundle.

Selection, and why it needs a resolver

The idea that's hardest to hold in your head

Every service gets a profile, so any subset can start. But profiles don't follow dependencies: asking for keycloak gives you a project referencing a Postgres that isn't there, and Compose correctly refuses it. Keycloak can't fix this by adding itself to Postgres's profile list — that would mean editing another module's file.

So the resolver expands a request into its transitive closure first. Pick modules below and watch what actually starts.

One decision that can't wait long

Not a version bump

Needs a decision

MinIO is archived

The newest pullable image is the one pinned here. The final upstream release fixed a privilege-escalation CVE at CVSS 8.1 — and shipped with zero assets, absent from Docker Hub and quay. Six further advisories have no community fix. Separately, the May 2025 release gutted the console: admin features and LDAP/OIDC moved to a commercial product, leaving an object browser.

It touches seeded buckets, the smoke test's object round-trip, the AWS_ENDPOINT_URL contract variable, and the console link in the README. The module is named object-storage rather than minio precisely so the swap doesn't collide with a frozen volume name.

Getting there without losing data

Eight stages · two carry real risk

Two orderings are forced. The task-runner question is settled before any CI is written, or that CI gets rewritten. And the eleven stale image pins are bumped after CI exists but before the file split — debugging a Tempo major upgrade and a refactor simultaneously is the worst available option.

00

pixi owns tasks

Shell logic moves out of Makefile recipes into testable scripts. No compose change at all. Done when lint fails on a machine without shellcheck — because pixi supplies it and it actually ran.

01

CI green on today's stack

Prove the harness against a known-good monolith before asking it to police a refactor.

02

Image bumps, one PR each

Eleven stale pins. Tempo 2→3 and Grafana 12→13 ship together — the span-metrics wiring spans both.

03

Extract the substrate + one modulerisk

Postgres first: no dependencies, so it isolates the mechanism. Compare rendered compose config before and after — it should be identical but for key ordering.

04

The remaining twelve

Batched by bundle. Volume identity checked after every batch.

05

Selection and bundlesbreaking

The visible change: a bare up goes from starting the core five to starting nothing, for anyone whose .env predates it. Mitigated three ways, and led with in the release notes.

06

Batteries

Dashboards, generated endpoint docs, multi-service backup, the non-destructive realm reimport, worked example.

07

Catalog

Broker, search, OpenBao, AWS emulation — each through admission first. Settle object storage before adding anything new.
