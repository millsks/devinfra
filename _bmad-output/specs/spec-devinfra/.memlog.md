- (question) GRAPH SEARCH IS AN UNMET NEED. User confirmed they need BOTH vector similarity (pgvector, covered) and graph traversal (not covered). pgvector does nearest-neighbour over embeddings, not node/edge traversal. The pgvector/pgvector image contains no graph extension. Risk being verified: Apache AGE has historically lagged Postgres major versions and may not support PG 17, which the stack pins deliberately to match an enterprise environment - a possible hard conflict between two stated requirements.
- (decision) GRAPH SEARCH OUT OF SCOPE - user decision. pgvector alone. Recorded as an explicit non-goal rather than an open question so it is not silently re-opened. Verification of Apache AGE's PG 17 support was stopped as no longer decision-relevant.
- (event) Verified against the running instance: PostgreSQL 17.8, pg_available_extensions offers only 'vector' and 'plpgsql' - no graph extension present. Installed: vector 0.8.1, pg_trgm, btree_gin, uuid-ossp, pg_stat_statements. pg_trgm and Postgres full-text cover lexical search; vector covers similarity. Nothing further is needed for the stated workloads.
- (decision) Graph search REOPENED and its shape decided: the graph is ABOUT THE POSTGRES DATA, not a separate domain. That rules out Neo4j - a separate graph database would create two sources of truth for data that already lives in one, with no JOINs and no shared transaction boundary. Apache AGE (in-Postgres extension) is the correct shape if it is available on PG 17.
- (note) Selection (CAP-2) materially changes the cost calculus for optional Services: a Module nobody selects costs nothing to have in the Catalog. The 'another container' objection that helped retire the broker and search engine applies much more weakly to a graph extension that ships inside an existing container.
- (question) DECISIVE, verification in flight: does Apache AGE support PostgreSQL 17? The stack pins PG 17 deliberately to match an enterprise environment, so 'downgrade to PG 16 for AGE' would trade one stated requirement for another. Also checking whether AGE and pgvector coexist (AGE needs shared_preload_libraries), and whether any image already bundles both.
- (event) VERIFIED: Apache AGE supports PG 17. AGE 1.7.0 released 2026-02-11 for PG17 (1.8.0 for PG18); ASF signed source releases exist; PG17 branch age.control declares default_version 1.7.0. Apache top-level project, actively maintained. My earlier 'AGE lags Postgres majors' warning was stale - true only until 2025-09-22.
- (event) CORRECTION: AGE does NOT require shared_preload_libraries; per-session LOAD 'age' is the documented path. I asserted the opposite twice.
- (constraint) AGE must NOT be added to shared_preload_libraries in this stack. Two open upstream issues (#2180, #2520) report AGE hooks breaking databases that lack ag_catalog - CREATE EXTENSION pg_stat_statements fails, TRUNCATE fails. This stack preloads pg_stat_statements AND creates extra databases (keycloak, app_test) that will not have AGE, so preloading would break it. Use per-session LOAD.
- (decision) Graph capability ADDED as FR-21/CAP-21: Apache AGE alongside pgvector in one Postgres instance. Delivered by a custom image FROM pgvector/pgvector:pg17 plus the PGDG package postgresql-17-age - no compilation. No trustworthy prebuilt combined image exists; the two community options have 3-4 stars and one has NO LICENCE, failing AD-20.
- (note) ARCHITECTURAL FIRST: devinfra currently builds no images - every Service is an upstream image plus config. This introduces the first built image, which means a CI build step, a rebuild on every base-image bump, and a new answer to what AD-11's 'pinned tag' means for an image we build. Flagged for the architect; may warrant an AD.
